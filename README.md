# 마고에듀 통합 클라우드

학원 프로그램(마고 타종, 오답노트 …)을 **한곳에서 설치·실행·업데이트**하고, **계정마다 데이터를 서버에 동기화**하는 프로그램이에요.
Adobe Creative Cloud 처럼 로그인하면 쓸 수 있는 프로그램이 보이고, 눌러서 설치하고 열면 돼요.

**구현민 개발**

---

## 무엇을 하나요

- **프로그램 관리** — 로그인하면 쓸 수 있는 프로그램 목록이 보이고, 설치·열기·업데이트·삭제를 할 수 있어요.
- **통합 클라우드에서만 실행** — 프로그램은 따로 설치할 수 없고, 통합 클라우드가 넘겨주는 실행 허가증(서버 서명)이 있어야 켜져요.
- **같은 아이디 = 같은 데이터** — 어느 컴퓨터에서 로그인하든 같은 데이터를 써요. 두 컴퓨터에서 동시에 고친 파일은 따로 보관해서 잃어버리지 않아요.
- **실시간 동기화** — 다른 기기에서 바꾸면 서버 알림으로 바로 받고, 이 컴퓨터에서 바꾸면 1초쯤 뒤에 올려요. 마고 타종은 PC와 안드로이드 앱이 시간표·종소리·오늘 설정·울린 기록을 함께 맞춰요.
- **바로 가기** — 설치한 프로그램은 바탕 화면·시작 메뉴 바로 가기로 켤 수 있어요. 로그인은 통합 클라우드에 그대로 있고, 누르면 통합 클라우드가 켜 줘요.
- **안드로이드 앱** — 프로그램 목록의 안드로이드 항목(예: 마고 타종 (안드로이드))은 휴대폰 브라우저에서 웹 버전에 로그인하고 내려받아요.
- **오래 안 쓴 큰 데이터 정리** — 오답노트 문제집처럼 용량이 큰 데이터는 정한 기간(기본 30일) 동안 안 쓰면 **서버에서만** 지우고 그 컴퓨터에는 남겨 둬요. 다시 열면 서버에 다시 올라가요.
- **자동 업데이트** — 통합 클라우드는 스스로, 프로그램은 통합 클라우드가 새 버전을 받아서 업데이트해요.
- **계정**
  - **운영자**: 원장 가입 코드 만들기, 계정 직접 만들기, 모든 계정·학원 관리, 프로그램 목록·보관 기간·서버 설정, 활동 기록
  - **원장**: 가입 코드로 직접 가입, 우리 학원 선생님 계정 만들기·삭제·비밀번호 초기화·사용 중지·프로그램 권한, 학원 공지
  - **선생님**: 프로그램 사용
  - **모든 계정**: 아이디·비밀번호·이름 바꾸기, 로그인한 컴퓨터 보기·원격 로그아웃
- **그 밖에** — 비밀번호 초기화, 로그인 기기 관리, 활동 기록, 계정 사용 중지, 예전 데이터 가져오기(따로 설치해 쓰던 데이터를 계정으로 옮기기), 공지사항, 저장 용량 표시·한도, 프로그램별 사용 권한

## 구성

```
server/     통합 클라우드 서버 (Node.js, 따로 설치할 라이브러리 없음, SQLite 내장)
launcher/   통합 클라우드 프로그램 (Windows, Electron) — 디자인은 마고 타종과 같아요
sdk/        프로그램을 통합 클라우드에 연결하는 파일 (Python, Node)
docs/       INTEGRATION.md — 오답노트·마고 타종을 연결하는 방법
```

```
 [통합 클라우드 (각 컴퓨터)] ──로그인·동기화·새 버전──▶ [서버] ──새 버전 찾기──▶ [GitHub Releases]
        │ 실행 허가증 + 데이터 폴더
        ▼
 [마고 타종] [오답노트] …
```

## 1. 서버 설치 (Ubuntu, `mago.milky.kr`)

처음 한 번만 하면 돼요. 그 뒤로는 main 에 올리면 GitHub Actions 가 알아서 서버를 업데이트해요.

### 준비

- **DNS**: `mago.milky.kr` 의 **A 레코드**를 서버의 공인 IP 로 정해 주세요.
- **포트**: 서버(또는 클라우드 보안 그룹·공유기)에서 **80, 443**(HTTPS)과 **22**(자동 배포용 SSH)를 열어 주세요.

### 설치 명령

서버에 SSH 로 들어가서:

```bash
git clone -b feature/magoedu-cloud https://github.com/hminkoo10/MagoEdu.git
```

```bash
sudo bash MagoEdu/server/deploy/install.sh --domain mago.milky.kr --setup-deploy
```

> 지금은 서버 파일이 `feature/magoedu-cloud` 브랜치에 있어서 `-b feature/magoedu-cloud` 가 필요해요. main 에 합친 뒤에는 빼도 돼요.

이 명령 하나가 알아서 해요.

1. Node.js 22 설치 (없으면)
2. 서버 설치 → `/opt/magoedu-cloud`, 데이터 → `/var/lib/magoedu-cloud`, 설정 → `/etc/magoedu-cloud.env`, 컴퓨터를 켜면 자동 실행
3. HTTPS: Caddy 를 설치하고 `https://mago.milky.kr` 인증서를 자동으로 받아요
4. 자동 배포 준비: 배포 전용 계정(`deploy`)과 접속 열쇠를 만들어요
5. 마지막에 **운영자 계정**과 **GitHub 에 넣을 값 두 개**를 화면에 보여 줘요

### GitHub 에 값 두 개 넣기

GitHub 의 MagoEdu 저장소 → **Settings → Secrets and variables → Actions → New repository secret** 에서, 설치 화면 마지막에 나온 값을 그대로 붙여 넣어요.

| 이름 | 무엇인가요 |
| --- | --- |
| `DEPLOY_SSH_KEY` | GitHub 가 서버에 들어올 때 쓰는 **열쇠**예요. `-----BEGIN` 줄부터 `-----END` 줄까지 전부 넣어요. |
| `DEPLOY_KNOWN_HOSTS` | 서버의 **지문**이에요. GitHub 가 접속할 때 "이게 진짜 mago.milky.kr 서버가 맞는지" 확인하는 데 써요. 누가 중간에서 가짜 서버로 바꿔치기해도 배포 파일을 넘기지 않게 막아 줘요. |

> `ssh-keyscan` 은 이 "서버 지문"을 밖에서 받아 오는 명령이에요. 설치 스크립트가 서버 안에서 지문을 바로 읽어 보여 주니까 직접 쓸 필요는 없어요.

다 넣었으면 끝이에요. 이제 main 에 `server/` 가 바뀌어 올라오면 자동으로 배포돼요. 손으로 하려면 **Actions → Deploy (서버) → Run workflow**.

### 자동 배포는 이렇게 동작해요

1. GitHub Actions 가 서버 시험을 돌리고 배포본을 만들어요.
2. SSH 로 서버에 올리고, 서버에서 **DB 백업 → 교체 → 다시 켜기 → 새 버전이 잘 켜졌는지 확인**까지 해요.
3. 새 버전이 안 켜지면 **바로 예전 버전으로 되돌리고** Actions 에 실패로 표시돼요. 서비스는 끊기지 않아요.

- DB 백업은 `/var/lib/magoedu-cloud/backups` 에 최근 10개를 남겨요. 직전 버전 프로그램은 `/opt/magoedu-cloud.prev` 에 있어요.
- `deploy` 계정은 배포 명령 하나만 관리자 권한으로 실행할 수 있어요. 그래도 `DEPLOY_SSH_KEY` 와 main 에 올릴 권한은 서버 관리자 권한처럼 다뤄 주세요.

### 자주 쓰는 명령

| 하고 싶은 것 | 명령 |
| --- | --- |
| 처음 운영자 비밀번호 다시 보기 | `sudo cat /var/lib/magoedu-cloud/INITIAL_ADMIN_PASSWORD.txt` |
| 서버 상태 | `systemctl status magoedu-cloud` |
| 서버 기록 보기 | `journalctl -u magoedu-cloud -f` |
| 설정 바꾼 뒤 다시 켜기 | `sudo systemctl restart magoedu-cloud` (설정 항목은 `server/.env.example`) |
| GitHub 값 다시 보기 | `sudo bash MagoEdu/server/deploy/install.sh --domain mago.milky.kr --setup-deploy` 를 다시 실행 (데이터·설정은 그대로) |

**백업**: 데이터 폴더 `/var/lib/magoedu-cloud` 하나만 복사하면 돼요. 안의 `keys/` 는 실행 허가증 서명 키라서 잃어버리면 모든 컴퓨터가 다시 로그인해야 해요.

### Docker 로 돌리고 싶다면

위의 설치 명령 대신 저장소의 `server` 폴더에서:

```bash
docker compose up -d
```

처음 운영자 비밀번호는 `docker compose logs` 에 나와요. (이 방법은 자동 배포 대신 `git pull` 후 `docker compose up -d --build` 로 업데이트해요)

## 2. 통합 클라우드 설치

- 웹 버전 로그인 화면의 **Windows 프로그램 내려받기**(`https://mago.milky.kr/download/launcher`)를 눌러요.
- 또는 [Releases](https://github.com/hminkoo10/MagoEdu/releases) 에서 `MagoEduCloud-Setup-x.y.z.exe`.
- 서버 주소 `https://mago.milky.kr` 이 미리 들어 있어서 바로 로그인하면 돼요. (다른 주소를 쓰려면 로그인 화면 아래의 서버 주소를 눌러 바꿔요)

### 웹에서 쓰기

- `https://mago.milky.kr` 을 브라우저로 열면 앱과 같은 화면의 **웹 버전**이 나와요. 같은 아이디로 로그인해요.
- **웹에서 되는 것**: 공지, 내 계정(아이디·비밀번호·이름, 로그인 기기), 선생님·계정 관리, 가입 코드, 프로그램 목록·활동 기록·서버 설정, 안드로이드 앱 내려받기(안드로이드 휴대폰에서 **내려받기**)
- **앱에서만 되는 것**: 프로그램 설치·실행·업데이트, 데이터 동기화, 예전 데이터 가져오기. Windows PC 브라우저에서 **PC에 설치**·**PC에서 실행**을 누르면 그 PC 의 통합 클라우드 앱이 열려서 설치하거나 실행해요. (앱이 없으면 내려받기 안내)
- 휴대폰·태블릿에서도 화면에 맞게 쓸 수 있어요. (메뉴는 왼쪽 위 버튼)

## 3. 처음 쓰는 순서

1. 운영자 계정으로 로그인 → 비밀번호 새로 정하기
2. **원장 가입 코드** 만들기 → 원장님께 코드 전달 (또는 **계정 관리**에서 원장 계정을 직접 만들기)
3. 원장님이 통합 클라우드에서 **원장 가입 코드가 있어요** 로 가입 → **선생님 관리**에서 선생님 계정 만들기
4. 모두 **프로그램** 화면에서 필요한 프로그램을 설치하고 열기

| | 운영자 | 원장 | 선생님 |
| --- | :---: | :---: | :---: |
| 프로그램 설치·실행, 아이디·비밀번호 바꾸기, 로그인 기기 관리 | ✓ | ✓ | ✓ |
| 선생님 계정 만들기·삭제·비밀번호 초기화·사용 중지·프로그램 권한 | 모든 학원 | 우리 학원 | |
| 공지 올리기 | 전체·학원 | 우리 학원 | |
| 원장 가입 코드, 원장·운영자 계정, 학원 관리 | ✓ | | |
| 프로그램 목록·보관 기간, 저장 용량 한도, 서버 설정, 활동 기록 | ✓ | | |

## 4. 데이터와 동기화

- 프로그램마다 **동기화 폴더**(서버와 맞춤)와 **이 컴퓨터 폴더**(캐시·기록)가 따로 있어요.
- 다른 기기에서 바뀌면 서버 실시간 알림으로 바로, 이 컴퓨터에서 바뀌면 1초쯤 뒤에 동기화해요. 그 밖에도 켜기 전·끈 뒤, 그리고 5분마다 맞춰요.
  인터넷이 끊겨도 프로그램은 그대로 쓸 수 있고, 연결되면 이어서 맞춰요.
- 인터넷 없이 프로그램을 켤 수 있는 기간은 운영자가 정해요(기본 7일).
- 저장 용량은 계정마다 기본 2GB 이고, 운영자가 계정별로 바꿀 수 있어요.

## 5. 업데이트와 배포

- **통합 클라우드**: `launcher/` 를 고쳐서 main 에 올리면 GitHub Actions 가 버전을 올리고 설치 파일을 Release(`cloud-vX.Y.Z`)로 올려요.
  서버가 이 Release 를 찾아서 설치된 통합 클라우드에 넘겨 주고, 켜진 프로그램이 없고 창이 닫혀 있을 때 조용히 업데이트해요.
- **프로그램**: 각 저장소의 Release 에 `이름-x.y.z-win-x64.zip` 을 올리면 서버가 10분 안에 찾아내고, 통합 클라우드가 받아서 설치해요.
  켜져 있는 프로그램은 다음에 켤 때 새 버전으로 바뀌어요. 자세한 것은 [docs/INTEGRATION.md](docs/INTEGRATION.md).
- **서버**: `server/` 나 화면(`launcher/src/renderer`)을 고쳐서 main 에 올리면 `mago.milky.kr` 서버에 자동으로 배포돼요. 화면은 웹 버전으로 같이 올라가요. (위 ‘서버 설치’)

## 개발

| 위치 | 명령 | 내용 |
| --- | --- | --- |
| `server` | `npm start` | 서버 켜기 (`server/.env` 읽음, 개발용). `launcher/src/renderer` 를 웹 버전으로 내보내요 (글꼴은 `launcher` 에서 `npm install` 한 번) |
| `server` | `npm test` | 계정·가입 코드·동기화·실시간 알림·보관 기간·프로그램 목록(안드로이드 포함)·내려받기 주소·허가증·자동 배포(되돌리기 포함)·웹 화면 시험 |
| `launcher` | `npm install` → `npm start` | 통합 클라우드 개발 모드 |
| `launcher` | `npm test` | 설치·업데이트·두 컴퓨터 동기화·실시간 동기화·충돌·보관 기간·예전 데이터·바로 가기·웹의 PC에 설치·인터넷 없이 실행·기기 알아보기 시험 (실제 서버와 함께) |
| `launcher` | `npm run test:ui` | 화면 전체 흐름 (리눅스는 `xvfb-run` 필요, 화면은 `test/out/`) |
| `launcher` | `npm run dist` | Windows 설치 파일 (`dist/`) |
| `sdk` | `npm test` | 실행 허가증 확인 (Python·Node) |

## 보안 메모

- 비밀번호는 scrypt 로 저장하고, 로그인은 10분에 8번까지만 틀릴 수 있어요.
- 이 컴퓨터의 로그인 정보는 Windows 계정으로 암호화해서(DPAPI) 저장해요.
- 실행 허가증은 서버만 가진 Ed25519 키로 서명해요. 프로그램은 공개 키로만 확인하므로, 프로그램 파일을 복사해도 통합 클라우드 없이는 켜지지 않아요.
- 계정을 사용 중지하거나 비밀번호를 초기화하면 그 계정은 모든 컴퓨터에서 바로 로그아웃돼요.
